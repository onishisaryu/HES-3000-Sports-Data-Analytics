# Part 1: Data Types & Measurement Scales\
\
---\
\
# Scales of Measurement in Performance Data\
\
- **Nominal (Categorical / Unordered):**\
  - *Definition:* Labels or categories without intrinsic numerical order.\
  - *Examples:* Player position (`PG`, `SG`, `SF`), play type (`Pick-and-Roll`, `Isolation`), outcome (`Make`, `Miss`).\
\
- **Ordinal (Ranked / Ordered Categories):**\
  - *Definition:* Categories with a distinct order, but uneven or unknown intervals between ranks.\
  - *Examples:* Player availability status (`Questionable`, `Doubtful`, `Out`), subjective RPE (`1` to `10`), draft board rankings.\
\
- **Practical Consideration:**\
  - You cannot take a meaningful average ($\\mu$) of nominal or ordinal variables!\
\
---\
\
# Continuous vs. Discrete Quantitative Data\
\
- **Discrete (Count Data):**\
  - *Definition:* Values restricted to distinct, whole numbers ($z \\in \\mathbb\{Z\}_\{\\ge 0\}$).\
  - *Examples:* Rebounds, goals scored, pass attempts, foul count.\
  - *Modeling Reality:* Poisson or Negative Binomial distributions (not Gaussian bell curves).\
\
- **Continuous (Measured Data):**\
  - *Definition:* Infinite possible values within a continuum ($x \\in \\mathbb\{R\}$).\
  - *Examples:* Sprint speed ($\\text\{m/s\}$), peak impact force ($\\text\{N\}$), jump height ($\\text\{cm\}$), heart rate recovery ($\\text\{bpm\}$).\
  - *Modeling Reality:* Often assumed Gaussian, but heavily subject to skewness in elite populations.\
\
---\
\
# Spatial & Temporal Data Types\
\
- **Spatial Coordinates ($x, y, z$):**\
  - *Definition:* Positional markers tracking location on a pitch, court, or rink relative to an origin $(0,0)$.\
  - *Examples:* Shot coordinates, defender tracking paths, player heatmaps.\
  - *Key Trait:* Requires spatial autocorrelation considerations (near points depend on each other).\
\
- **Temporal / Time-Series Streams ($t$):**\
  - *Definition:* Sequential measurements ordered across time increments.\
  - *Examples:* 10Hz GPS velocity profiles, possession elapsed time, season-long cumulative load.\
  - *Key Trait:* High temporal autocorrelation (a player's speed at frame $t$ heavily predicts speed at frame $t+1$).\
\

# Part 2: Data Structure & Dimensionality\
\
---\
\
# Data Structure: Wide vs. Long Formats\
\
- **Wide Format (Spreadsheet Native):**\
  - Each subject gets one single row; multiple time points or tests are spread across columns.\
  - *Example:* `Player_ID | Jump_Height_Week1 | Jump_Height_Week2 | Jump_Height_Week3`\
  - *Use Case:* Easy for human viewing in Excel, quick univariate comparisons.\
\
- **Long Format (Tidy / Analytics Native):**\
  - Each row represents a single observation per time point per entity.\
  - *Example:* `Player_ID | Week | Jump_Height`\
  - *Use Case:* Required for group comparisons, time-series plotting (`ggplot2`), and multilevel modeling in R.\
\
- **Rule of Thumb:** Store data long; reshape wide only for executive summaries or dashboards.\
\
---\
\
# Sampling Frequency & Data Volume\
\
- **Frequency ($Hz = \\text\{samples per second\}$):**\
  - **1 Hz (Macro):** Event logs, box scores, daily wellness survey responses.\
  - **10 Hz (Wearable/GPS):** Player tracking coordinates, velocity, accelerations (10 snapshots/sec).\
  - **100 Hz - 1000 Hz (Biomechanics):** Raw force plate signals, EMG, 3D motion capture.\
\
- **The Trade-Off:**\
  - Higher sampling frequency = Higher fidelity to capture rapid movement (e.g., rate of force development).\
  - Higher sampling frequency = Exponential expansion of file sizes and processing overhead.\
\

# Part 3: Signal vs. Noise & Measurement Errors\
\
---\
\
# Defining Signal, Noise, and Error\
\
- **The Observed Value Equation:**\
\
$$\\text\{Observed Measurement\} = \\text\{True Value\} + \\text\{Systematic Error\} + \\text\{Random Noise\}$$\
\
- **Signal:**\
  - The true underlying physical phenomenon or tactical behavior you are trying to measure.\
\
- **Noise:**\
  - Unwanted, random fluctuations that obscure the true signal (e.g., electrical interference, slight sensor movement).\
\
- **Error:**\
  - Systematic bias or distortion introduced during the collection process.\
\
---\
\
# Sources of Noise & Error in Sports Data\
\
- **1. Hardware & Sensor Noise:**\
  - Satellite loss in GPS units near stadium roofs, sensor displacement inside a tight jersey vest.\
\
- **2. Environmental Interference:**\
  - Temperature fluctuations affecting metabolic carts, indoor signal bounce for Local Positioning Systems (LPS).\
\
- **3. Human & Observational Bias:**\
  - Inter-operator variability in video tagging (e.g., Home scorer recording more generous assist/tackle counts).\
\
- **4. Sensor Drift:**\
  - Mechanical or thermal calibration shifting over the course of a 2-hour game or a full season.\
\
---\
\
# Identifying Outliers vs. Genuine Extremes\
\
- **The Analytics Dilemma:** Is an extreme data point a sensor glitch or elite performance?\
\
- **Data Artifact (Noise):**\
  - *Example:* A GPS vest recording a peak speed of $48 \\text\{ km/h\}$ for a soccer player due to satellite dropping.\
  - *Action:* Must be filtered or truncated (physiologically impossible human speed).\
\
- **True Outlier (Signal):**\
  - *Example:* An NBA player recording a 48-inch Countermovement Jump height on force plates.\
  - *Action:* Must be retained\'97this represents elite athletic outlier performance.\
\
- **Rule:** Never delete an outlier without domain context explaining *why* it is physically impossible!\
\

# Part 4: Missingness & Data Anomalies\
\
---\
\
# Types of Missing Data in Sports\
\
- **1. Missing Completely at Random (MCAR):**\
  - Missingness has no relationship to any observed or unobserved variable.\
  - *Example:* A GPS vest battery randomly dies on 1 athlete halfway through practice.\
\
- **2. Missing at Random (MAR):**\
  - Missingness is systematically related to an observed variable, but not the missing value itself.\
  - *Example:* Bench players have missing tracking data because they play fewer minutes (predictable via playing time).\
\
- **3. Missing Not at Random (MNAR / Structural Missingness):**\
  - Missingness depends directly on the unobserved value itself.\
  - *Example:* An injured athlete does not complete a weekly jump test *because* their fatigue/pain level is too high.\
\
---\
\
# Handling Missing Data: Common Pitfalls\
\
- **Pitfall 1: Complete Case Analysis (Listwise Deletion)**\
  - Deleting all rows with *any* missing variable.\
  - *Risk:* Dramatically reduces sample size and introduces severe selection bias if data is MNAR.\
\
- **Pitfall 2: Mean Imputation**\
  - Replacing missing cells with the overall column average.\
  - *Risk:* Artificially shrinks variance ($\\sigma^2$) and distorts true physiological relationships.\
\
- **The Pragmatic Approach:**\
  - Identify *why* data is missing first.\
  - For minor MCAR: Simple imputation or filtering.\
  - For structural MNAR: Document the missingness context explicitly (e.g., treat "Did Not Play" as a distinct state, not `NA`).\
  \

# Workshop Solutions & Share-Out\
\
- **1. Scale/Type Mismatch:** `Readiness` mixes categorical text (`High`, `Low`) with numeric strings (`8/10`). R will parse this entire column as `character`!\
- **2. Unrealistic Speed Outlier (Noise):** `Peak_Speed_mph = 42.1` for ID 104 is humanly impossible (Usain Bolt peaked ~27.8 mph). This is a sensor glitch/GPS spike.\
- **3. Improbable Distance (Sampling/Data Error):** `GPS_Dist_m = 12400` (~7.7 miles) in a single basketball session vs. `0` for an active player.\
- **4. Structural Missingness (MNAR):** `Session_RPE = DNP` for ID 104. "Did Not Play" is a structural state, not a missing numerical value.\
- **5. MAR/MCAR Missingness:** `Peak_Speed_mph = NA` for ID 102 (Center). Is it sensor failure (MCAR) or did the player not perform high-speed runs (MAR)?\
\

# Data Characteristics Checklist for Your CSV\
\
Before running analyses for your project, verify these 5 attributes:\
\
- [ ] **1. Granularity:** Is 1 row a season, game, possession, or frame?\
- [ ] **2. Data Types:** Are numerical columns parsed as numeric/double rather than character strings in R?\
- [ ] **3. Format Structure:** Is the dataset tidy (long format) for plotting and modeling?\
- [ ] **4. Range Limits:** Are all values within physiologically or rules-based bounds (e.g., $0-100\\%$ accuracy, realistic top speeds)?\
- [ ] **5. Missingness Audit:** Have you identified `NA` values and determined if they are random or structural?\
